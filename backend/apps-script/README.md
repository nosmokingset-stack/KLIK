# KLIK Orders: підготовка приватної таблиці

## Оптимізація довідника — 2026-11-27

Оновлений `Directory.gs` додано у вихідний проєкт **KLIK Orders** і перевірено read-only функцією `testPointSearchReadOnly`. Робоче web-app розгортання не оновлювалося. **Для активації `pointsSearch` потрібне повторне розгортання KLIK**: нова версія в наявному розгортанні зі збереженням його URL і параметрів доступу. Не розгортайте скрипт іншого магазину й не змінюйте його налаштування.

Новий публічний метод `pointsSearch` приймає `city` (SettlementRef) та `q`, виконує один `getWarehouses` із `FindByString` та обмеженням 50 сирих рядків; активні відділення й поштомати відбираються тим самим фільтром. Підтримуються українські та російські поля адрес/назв. Запити `cities`/`health` оголошують можливість `features.pointSearch`. Старі `points`/`page`, перевірка Ref при замовленні, обмеження частоти й логіка збереження замовлень залишаються сумісними.

Клієнт автоматично використовує новий метод після оголошення можливості. До повторного розгортання він сумісний зі старим сервером: перша сторінка відображається відразу, решта надходить у фоні. Кеш браузера зберігає лише публічні дані довідника на 3 хвилини; дані покупця не кешуються. Не потрібно міняти API-ключ, таблицю, прийом замовлень чи юридичні версії.

Повний звіт, заміри та обмеження — `NP-SEARCH-REPORT.md` у корені репозиторію. Read-only тест не відкриває аркуші, не створює замовлень і не надсилає листів.

Це незавершена частина V1.5. Розгорнутий інтерфейс доступний лише для пошуку довідника; створення замовлень не підключено. Приватні функції замовлення і листа є прототипом. Перевірку точки доставки за SettlementRef і Ref реалізовано, але не випробувано на реальному API і не готово до використання. Тема Blogger залишається V1.4.

- Проєкт Apps Script має бути прив’язаний до **нової приватної** таблиці «KLIK – Замовлення». Не використовуйте скрипт або таблицю іншого магазину.
- У налаштуваннях проєкту, у розділі Script Properties, власник додає `NOVA_POSHTA_API_KEY`. Не записуйте ключ у таблицю, код або журнал.
- Після перезавантаження таблиці меню **KLIK → Підготувати таблицю** запускає ініціалізацію. Перше виконання може запитати дозволи Google. З'являться п'ять аркушів: замовлення, налаштування, статистика, відділення й журнал. Прийом замовлень та синій колір початково вимкнені.
- Пошук населених пунктів і точок доставки використовує прямі запити до Нової пошти з коротким кешем CacheService. Окремий довідник у таблиці та щоденне оновлення не потрібні. Старий аркуш, створений попередньою версією, код більше не використовує.
- Статистика трактує отримані замовлення за їхнім статусом, не як підтвердження банківського платежу. Часткові повернення не відображаються окремо.

Перед підключенням форми потрібні перевірка реальної відповіді API, завершення серверної обробки замовлень і окремий тестовий запуск. Ідентифікатори приватних ресурсів та облікові дані не входять до цих вихідних файлів.
